## 2026-11-07, smartmove-site (minis): two silent misses, a work outside OpenAlex's list index and a tag lost to a merge

- **Provenance:** smartmove-site session, 2026-11-07, minis, erga 0.9.3 (`uvx erga==0.9.3 build --config _data/erga.yml`, keyed). Found while checking why the Ro-Boat Race 2023 dataset never listed; the second surfaced in the same local build's warnings.
- **1. A matched work outside the list index.** `10.5281/zenodo.13318421` ("The Aegean Ro-Boat Race 2023: the dataset") is `W6949021637`: `GET /works/https://doi.org/10.5281/zenodo.13318421` returns it with five tracked members carrying their configured author ids (A5022008164, A5054072214, A5043982111, A5052208676, A5076536574). Yet `/works?filter=doi:10.5281/zenodo.13318421`, `filter=openalex_id:W6949021637`, a quoted title `search`, and `filter=author.id:<each of those ids>,doi:...` all return count 0. Positive control: `filter=author.id:A5043982111,doi:10.1109/maes.2024.3425317` returns 1. So no profile fetch can see it and nothing warns. Whether `erga verify` can see it is untested here (its 2026-10-17 run found the AegeaNET dataset, a different fault: in the index, member authorships without ids). The record merges the concept and version DOIs (`...13318421`, `...13318422`), updated 2026-10-14, created 2025-10-10; why the index lacks it is not known here. Worked around with a manual entry.
- **2. A curation tag lost to a merge.** The bot build of 2026-11-04 (smartmove-site commit `5004398`) removed `W4247865621`, the featured IJBDI 2020 paper under `10.1504/ijbdi.2020.107375`. OpenAlex had merged it into `W3026107496`, whose main `doi` is `10.1504/ijbdi.2020.10029526`; the old DOI survives only in `locations`. The paper kept listing, but `publications_tags.yml` names the old DOI, so the featured tag matched nothing and the Research page showed 11 featured instead of 12 for three days. The only signal was `erga: warning: tag matched nothing: tag 'featured': https://doi.org/10.1504/ijbdi.2020.107375` in a CI log nobody reads (the summary line's tag-change count likewise). Fixed here by retagging the new DOI. Overrides and manual-entry DOIs match the same way, so presumably share the exposure (not tested).
- **Trigger:** both are silent in a consumer's daily path, CI, where warnings are not read. What erga does about either is erga's call.
